2. 🔴 L'ESSAI EST BLOQUE PAR UN OBSTACLE MESURE, ⛔ PAS SUPPOSE
==============================================================================

  Le premier geste de l'essai — publier le workflow pour que
  `pull_request_target` puisse se declencher — a ete REFUSE PAR GITHUB :

    $ git push origin main
    ! [remote rejected] main -> main (refusing to allow an OAuth App to
      create or update workflow `.github/workflows/cla.yml` without
      `workflow` scope)
    error: failed to push some refs to 'https://github.com/nasbarok/desknode.git'

  MESURE de l'identification en place :
    $ gh auth status
      Token scopes: 'gist', 'read:org', 'repo'      ⇒ ⛔ pas de `workflow`

  ⇒ 🎯 CONSTAT QUI N'ETAIT DANS AUCUN CADRAGE, ET QUI VAUT D'ETRE ECRIT :
     **le scope `repo` NE SUFFIT PAS a publier un fichier de `.github/
     workflows/`.** GitHub refuse la reference cote SERVEUR, ⛔ pas cote
     client — le commit local est propre, c'est la PUBLICATION qui tombe.
     Un cadrage qui aurait conclu « il suffit de poser le fichier » se
     serait trompe. C'est precisement pourquoi AC2.4 exige L'ESSAI.

  ⚠️ CE QUE CET OBSTACLE NE DIT PAS : il ne dit RIEN sur le bot lui-meme.
     Il est ANTERIEUR — il porte sur le droit de publier un workflow, ⛔ pas
     sur son execution. ⛔ Ne pas conclure « le bot ne marche pas ».

  LEVEE : un geste de l'owner, ⛔ pas du dev — l'octroi de scope passe par
          un flux navigateur :
            gh auth refresh -h github.com -s workflow -s user
