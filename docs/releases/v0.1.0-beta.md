# DeskNode v0.1.0-beta — 2026-09-14

*Release notes dated 2026-09-14. This release was published on 2026-09-14 as a pre-release, while this repository is still private.*

**DeskNode** is a physical desktop dashboard: a small touchscreen that sits next to your PC and shows, at a glance, what the machine and the room around it are doing. What it is, what it shows and what to buy: the [front page](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/README.md).

What to expect from this project — maintenance, support, feature requests — is written in one place, and these notes do not repeat it: [What this project is, honestly](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/CONTRIBUTING.md#what-this-project-is-honestly).

## What is attached

- **The firmware payload that the install page writes on the board**: `bootloader.bin`, `partition-table.bin`, `desknode.bin` and `living_pcb_v0.bin`, plus `manifest.json`, which says where each one goes. Their offsets, sizes and SHA-256 hashes, and the command that produced them, are in [`installeur/charge/PROVENANCE.md`](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/installeur/charge/PROVENANCE.md) (in French). They are not copied here: there is one table to check the downloaded files against, and it is that one.
- **`desknode-v0.1.0-beta.zip`, the whole tree of this tag**, made with `git archive`. It carries the Windows agent (`agent/`) and the installer (`installeur/`), which expects the rest of the repository next to it. Its content is the tag's, like GitHub's own *Source code (zip)*; the difference is that the hash of these exact bytes is shown with the asset.
- ⛔ **No standalone executable for the agent** — see *Declared gaps*.

## Where the firmware comes from

`desknode.bin` was built from commit `55006c19182b3ff1ccc017044057347841ede475`, and the `firmware/` directory of the tag `v0.1.0-beta` is identical to that commit's. It is the build that was flashed on the development board and read on its screen on 2026-09-13, where the menu header shows `version 55006c1`; the provenance file names the session. ⚠️ Rebuilding from the tag does ⛔ not reproduce these bytes: the build time is embedded in the binary, and `sdkconfig` and `dependencies.lock` are not in the repository (see [*Building the firmware*](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/CONTRIBUTING.md#building-the-firmware)); the hashes of the provenance file identify **this** build, ⛔ not any build of this commit. The firmware is licensed **GPL-3.0-or-later**, and what that means for these binaries is in [`LICENSING.md`, *Binary releases*](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/LICENSING.md#binary-releases).

## Declared gaps

- **The binaries were built by hand, and no CI builds this firmware.** Nothing mechanises their provenance: what ties them to their revision is the version read out of `desknode.bin` and the hashes of the provenance file. `living_pcb_v0.bin` is not even a compiler output — it comes out of `tools/gen_living_pcb.py`. This gap is carried by `dn4-45`, *building the firmware in CI*.
- **Activating the agent from a downloaded copy is expected to fail** — with exit code `3`, because the launcher looks for the agent next to itself, a layout only the author's own deployment script produces. Established by reading the launcher, ⛔ not yet observed on a downloaded copy: see [*Known issues*](https://github.com/nasbarok/desknode/blob/v0.1.0-beta/README.md#known-issues).
- **No standalone executable for the agent.** The agent needs Python 3 and two modules, `psutil` and `pyserial`, today; a standalone executable is planned for **V0.2**.
- **Flashing this exact binary from the install page has not been replayed.** The page was proven end to end on the previous payload; the session of 2026-09-13 flashed this one with `idf.py`.
